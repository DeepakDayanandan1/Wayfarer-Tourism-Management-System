1. PROJECT OVERVIEW & SYSTEM DOMAIN
================================================================================
Wayfarer is an enterprise-grade, monolithic Tourism and Holiday Package Management
web platform engineered on the Laravel framework. Designed for travel agencies,
destination management companies (DMCs), and modern holidaymakers, Wayfarer
bridges traveler customer self-service with centralized operational administration.

The application serves two distinct user personas through isolated guards:
1. Travelers (Public & Authenticated Customers):
   - Browse holiday packages by type (Family, Couples, Adventure), location, and budget.
   - Select departure and return dates with dynamic calendar validation.
   - Submit real-time reservations and receive instant confirmation vouchers.
   - Manage profiles with a custom initial avatar pill interface.
   - Track active, confirmed, and historical bookings with cancellation capabilities.
   - Raise support issue tickets and submit custom tour requests.
2. Operations Administrators (Command Center):
   - Monitor real-time KPIs and business intelligence via a central dashboard.
   - Manage the package inventory (CRUD, image uploads, price structures, location tags).
   - Review and fulfill reservations (Confirm, Cancel, and Audit).
   - Resolve customer support tickets with administrative remark logs.
   - Audit customer histories across registered traveler profiles.
   - Edit live informational pages (Terms, Privacy, About, Contact) via CMS.

4. MVC ARCHITECTURE & REQUEST LIFECYCLE
================================================================================
Wayfarer adheres to the standard Model-View-Controller architecture:

1. Entry Point:
   Every HTTP request enters via public/index.php.
2. Application Bootstrap:
   bootstrap/app.php initializes the application container, registers global
   middleware (EncryptCookies, StartSession, ShareErrorsFromSession,
   PreventRequestForgery, SubstituteBindings), and binds routing definitions.
3. Route Matching (routes/web.php):
   - Requests without /admin/ prefix match public traveler routes.
   - Requests with /admin/ prefix route into the admin group with prefix('admin').
4. Middleware Gateways:
   - 'guest.admin': Redirects authenticated administrators away from /admin/login.
   - 'admin': Enforces Auth::guard('admin')->check(), redirecting unauthorized
     requests to route('admin.login').
   - 'auth': Protects traveler accounts (/profile, /tour-history, /change-password).
5. Controller Execution:
   The controller handles domain logic, validates input data, communicates with
   Eloquent models, and passes data to Blade views.
6. View Rendering:
   Blade compiles templates into cached PHP files in storage/framework/views/.
   The compiled HTML is streamed back to the client as an HTTP response.

5. DATABASE SCHEMA, DICTIONARY & ELOQUENT MODELS
================================================================================
The application database contains 7 primary relational tables:

1. TABLE: `admin` (Eloquent Model: `App\Models\Admin`)
   Stores administrative staff credentials and contact information.
   - `id`: int(11) AUTO_INCREMENT, Primary Key
   - `UserName`: varchar(100), Administrator login handle (e.g., 'admin')
   - `Name`: varchar(150), Full legal name of administrator
   - `EmailId`: varchar(100), Administrator email (supports login)
   - `MobileNumber`: char(10), 10-digit mobile phone number
   - `Password`: varchar(255), Hashed authentication credential (Bcrypt)
   - `updationDate`: timestamp ON UPDATE current_timestamp()

2. TABLE: `tblusers` (Eloquent Model: `App\Models\User`)
   Stores registered traveler customer accounts.
   - `id`: int(11) AUTO_INCREMENT, Primary Key
   - `FullName`: varchar(100), Full name of traveler
   - `MobileNumber`: char(10), 10-digit primary mobile contact
   - `EmailId`: varchar(70), Unique email identifier & login username
   - `Password`: varchar(255), Hashed authentication credential (Bcrypt)
   - `RegDate`: timestamp DEFAULT current_timestamp(), Registration date
   - `UpdationDate`: timestamp ON UPDATE current_timestamp()
   Relationships:
   - hasMany Booking (`UserEmail` -> `EmailId`)
   - hasMany Issue (`UserEmail` -> `EmailId`)

3. TABLE: `tbltourpackages` (Eloquent Model: `App\Models\TourPackage`)
   Stores the tour package catalog, itineraries, and price structures.
   - `PackageId`: int(11) AUTO_INCREMENT, Primary Key
   - `PackageName`: varchar(200), Package title (e.g., 'Kerala Backwaters Tour')
   - `PackageType`: varchar(100), Category ('Family', 'Couples', 'Adventure')
   - `PackageLocation`: varchar(100), Geographical destination
   - `PackagePrice`: decimal(10,2), Base package rate per person
   - `PackageFetures`: varchar(255), Comma-separated package inclusions
   - `PackageDetails`: mediumtext, Comprehensive day-by-day itinerary & details
   - `PackageImage`: varchar(255), Relative path or filename in public/pacakgeimages/
   - `Creationdate`: timestamp DEFAULT current_timestamp()
   - `UpdationDate`: timestamp ON UPDATE current_timestamp()
   Relationships:
   - hasMany Booking (`PackageId` -> `PackageId`)

4. TABLE: `tblbooking` (Eloquent Model: `App\Models\Booking`)
   Stores holiday reservations created by travelers.
   - `BookingId`: int(11) AUTO_INCREMENT, Primary Key
   - `PackageId`: int(11), Foreign reference to `tbltourpackages.PackageId`
   - `UserEmail`: varchar(100), Traveler email reference
   - `FromDate`: varchar(100), Departure date (YYYY-MM-DD)
   - `ToDate`: varchar(100), Return date (YYYY-MM-DD)
   - `Comment`: mediumtext, Traveler special requests, passenger counts, notes
   - `RegDate`: timestamp DEFAULT current_timestamp(), Booking submission time
   - `status`: int(11), State machine: 0 = Pending, 1 = Confirmed, 2 = Cancelled
   - `CancelledBy`: varchar(5), 'u' (Cancelled by User) or 'a' (by Admin)
   - `UpdationDate`: timestamp ON UPDATE current_timestamp()
   Relationships:
   - belongsTo TourPackage (`PackageId` -> `PackageId`)
   - belongsTo User (`UserEmail` -> `EmailId`)

5. TABLE: `tblenquiry` (Eloquent Model: `App\Models\Enquiry`)
   Stores public contact submissions and custom vacation inquiries.
   - `id`: int(11) AUTO_INCREMENT, Primary Key
   - `FullName`: varchar(100), Traveler contact name
   - `EmailId`: varchar(100), Contact email address
   - `MobileNumber`: char(10), Contact phone number
   - `Subject`: varchar(150), Inquiry subject line
   - `Description`: mediumtext, Detailed message or custom travel request
   - `PostingDate`: timestamp DEFAULT current_timestamp()
   - `Status`: int(1), Read/Unread flag: 0/NULL = Unread, 1 = Read

6. TABLE: `tblissues` (Eloquent Model: `App\Models\Issue`)
   Stores customer service tickets raised by travelers.
   - `id`: int(11) AUTO_INCREMENT, Primary Key
   - `UserEmail`: varchar(100), Submitting traveler's account email
   - `Issue`: varchar(100), Category ('Booking Issues', 'Cancellation', 'Refund')
   - `Description`: mediumtext, Detailed description of problem
   - `PostingDate`: timestamp DEFAULT current_timestamp()
   - `AdminRemark`: mediumtext, Official administrative resolution note
   - `AdminremarkDate`: timestamp, Timestamp of administrator remark
   Relationships:
   - belongsTo User (`UserEmail` -> `EmailId`)

7. TABLE: `tblpages` (Eloquent Model: `App\Models\Page`)
   Stores static content managed via the administrative CMS.
   - `id`: int(11) AUTO_INCREMENT, Primary Key
   - `type`: varchar(50), Unique slug ('terms', 'privacy', 'aboutus', 'contact')
   - `detail`: longtext, HTML content rendered on public CMS pages

8. SECURITY, AUTHENTICATION & HARDENING ARCHITECTURE
================================================================================

1. Multi-Guard Authentication Architecture:
   - Configured in `config/auth.php`.
   - Guard `web`: Drives the traveler portal using Eloquent provider on `App\Models\User`.
   - Guard `admin`: Drives the operations dashboard using Eloquent provider on `App\Models\Admin`.
   - Complete session separation prevents session fixation or cross-guard escalation.

2. Multi-Tier Safe Password Verification:
   - Implemented across Login, Admin Login, and Profile updates.
   - Primary: Standard Bcrypt / Argon2 algorithms verified via `Hash::check()`.
   - Fallback: Gracefully validates multi-format credentials using timing-attack-safe
     `hash_equals()`, preventing runtime exception halts.
   - Seamless Upgrade: Upon successful authentication, passwords are automatically
     rehashed with Bcrypt (cost factor 12) and saved to the database.

3. Cross-Site Request Forgery (CSRF) Prevention:
   - Enforced across all POST, PUT, PATCH, and DELETE requests via
     `Illuminate\Foundation\Http\Middleware\PreventRequestForgery`.
   - Form templates embed `@csrf` directive generating hidden input tokens.

4. SQL Injection Immunity:
   - Database interaction relies on Laravel's Query Builder and Eloquent ORM.
   - PDO uses parameterized prepared statements with explicit binding for all queries.

5. Cross-Site Scripting (XSS) Mitigation:
   - Blade templates automatically escape variables using `{{ ... }}` (htmlspecialchars).
   - Unescaped `{!! ... !!}` syntax is strictly limited to sanitized CMS page bodies.

6. Schema Tolerance & Remember Token Safeguards:
   - Both `User` and `Admin` models implement `getRememberTokenName() { return ''; }`
     to prevent runtime SQL exceptions on schemas without `remember_token` columns.

10. LOCAL SETUP, POWERSHELL RUNNER & DEPLOYMENT
================================================================================

Local Setup Steps:
1. Ensure PHP 8.2+ and Composer are installed and available in PATH.
2. Clone repository and navigate to root:
   git clone <repo-url>
   cd Wayfarer
3. Install dependencies:
   composer install
4. Create environment file:
   copy .env.example .env   (or verify existing .env)
5. Generate application key:
   php artisan key:generate
6. Verify database credentials in .env:
   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=tms
   DB_USERNAME=root
   DB_PASSWORD=your_password
7. Provision database:
   mysql -u root -p tms < database/tms.sql
8. Launch application:
   Using PowerShell:
   .\run.ps1
   Or using Artisan CLI:
   php artisan serve --host=127.0.0.1 --port=8000

Production Deployment Checklist:
1. Set `APP_ENV=production` and `APP_DEBUG=false` in `.env`.
2. Cache configuration and routes:
   php artisan config:cache
   php artisan route:cache
   php artisan view:cache
3. Configure web server document root to point to the `public/` directory.
4. Ensure `storage/` and `bootstrap/cache/` directories are writable by the web server.
